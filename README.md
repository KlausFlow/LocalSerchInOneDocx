# Local RAG по одному документу

## Назначение

Скрипт позволяет задавать вопросы к одному `txt`-документу. Документ разбивается на фрагменты, затем локальный retrieval выбирает релевантные источники, а простой extractive-answerer формирует ответ только по найденным фрагментам.

Решение работает локально: без внешних LLM, векторных баз данных и высокоуровневых RAG-фреймворков.

## Структура проекта

- `rag_query.py` - основной CLI-скрипт.
- `requirements.txt` - зависимости.
- `README.md` - описание проекта и инструкция по запуску.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
python rag_query.py --document ./document.txt --question "Какая цель программы?"
```

Расширенный пример:

```bash
python rag_query.py --document ./document.txt --question "Какая цель программы?" --chunk-size 80 --overlap 20 --top-k 3
```

## Параметры CLI

- `--document` - путь к `txt`-документу.
- `--question` - вопрос пользователя.
- `--chunk-size` - размер чанка в словах, по умолчанию `80`.
- `--overlap` - перекрытие чанков, по умолчанию `20`.
- `--top-k` - число возвращаемых источников, по умолчанию `3`.
- `--retriever` - тип retrieval, сейчас `hybrid`.
- `--answerer` - тип answerer, сейчас `simple`.

## Пример вывода

```text
Вопрос:
Какая цель программы?

Ответ:
Программа предназначена для поиска ответов по одному текстовому файлу.

Источники:
1) chunk 1, score=1.000, words=1-80
Программа предназначена для поиска ответов по одному текстовому файлу...

2) chunk 2, score=0.742, words=61-140
Retrieval выбирает релевантные фрагменты документа...
```

Если релевантных источников нет:

```text
Вопрос:
Какая погода завтра?

Ответ:
В документе нет достаточной информации для ответа.

Источники:
Релевантные фрагменты не найдены.
```

## Принцип работы

1. Загрузка `txt`-документа.
2. Нормализация текста.
3. Чанкинг по словам.
4. Поиск релевантных фрагментов.
5. Формирование extractive-ответа.
6. Вывод вопроса, ответа и источников.

## Чанкинг

Текст режется по словам через `text.split()`.

- `chunk_size` - базовый размер чанка.
- `overlap` - перекрытие между чанками.
- Если хвост после последнего полного чанка `<= 40%` от `chunk_size`, он приклеивается к последнему чанку.
- Если хвост `> 40%` от `chunk_size`, создаётся отдельный чанк.
- Последний чанк может быть больше `chunk_size`.

Границы чанков выводятся как 1-based inclusive, например `words=1-80`.

## Retrieval

Retrieval выполняется локально и прозрачно:

- BM25 по словам;
- TF-IDF по символьным n-граммам;
- `hybrid score = 0.6 * BM25 + 0.4 * TF-IDF`;
- `MIN_RETRIEVAL_SCORE = 0.45`;
- фрагменты ниже порога не выводятся как источники;
- если релевантных фрагментов нет, система сообщает, что информации недостаточно.

## Answerer

`simple` answerer является extractive-компрессором:

- выбирает предложения только из найденных чанков;
- не использует весь документ целиком;
- не использует внешнюю LLM;
- не генерирует факты из внутренних знаний.

Если источников нет, возвращается:

```text
В документе нет достаточной информации для ответа.
```

## Ограничения

- Поддерживается только `.txt`.
- Ожидается UTF-8; UTF-8 с BOM также поддерживается.
- `pdf` и `docx` не поддерживаются.
- Внешние LLM не используются.
- Высокоуровневые RAG-фреймворки не используются.
- Качество ответа зависит от размера чанков, overlap и формулировки вопроса.
- Answerer простой extractive, поэтому ответ может быть менее гладким, чем у LLM.
