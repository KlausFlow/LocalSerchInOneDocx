# MVP RAG по одному документу

Проект реализует минимальный прототип RAG-пайплайна для ответов на вопросы по одному `txt`-документу. Документ не должен передаваться в ответчик целиком: сначала будет выполняться retrieval по фрагментам, затем ответ будет строиться по найденному контексту.

На текущем этапе реализованы CLI, проверки аргументов, загрузка `txt`-документа, нормализация текста, чанкинг по словам, локальный retrieval, simple answerer и финальный консольный вывод вопроса, ответа и источников.

## Состав сдачи

- `rag_query.py` - основной скрипт CLI.
- `requirements.txt` - базовые зависимости MVP.
- `README.md` - описание состава, параметров и ограничений.
- `.gitignore` - правила исключения локальных и служебных файлов.

## Формат документа

В первой версии поддерживается только текстовый файл `.txt`. Кодировка ожидается UTF-8; файлы с BOM также обрабатываются. `pdf` и `docx` пока не поддерживаются и должны давать понятную ошибку.

## Retrieval

Retrieval локальный и прозрачный: без внешних БД, сложных RAG-фреймворков и скрытых индексов. MVP работает с понятными текстовыми фрагментами и локальным ранжированием.

На текущем этапе используется `hybrid` retrieval:

- BM25 по словам;
- TF-IDF по символьным n-граммам;
- `hybrid score = 0.6 * BM25 + 0.4 * TF-IDF`;
- возвращается до `top_k` источников;
- если итоговый score нулевой, релевантные фрагменты считаются не найденными.
- применяется минимальный порог релевантности `MIN_RETRIEVAL_SCORE = 0.45`;
- фрагменты ниже порога не выводятся как найденные источники;
- если все score ниже порога, считается, что релевантные фрагменты не найдены.

## Базовые параметры

- `chunk_size=80`
- `overlap=20`
- `top_k=3`
- `retriever=hybrid`
- `answerer=simple`

## CLI-параметры

- `--document` - путь к `txt`-документу.
- `--question` - вопрос пользователя.
- `--chunk-size` - размер чанка в словах, по умолчанию `80`.
- `--overlap` - перекрытие чанков, по умолчанию `20`.
- `--top-k` - число источников, по умолчанию `3`.
- `--retriever` - тип retrieval, пока только `hybrid`.
- `--answerer` - тип answerer, пока только `simple`.

## Чанкинг

Текст режется по словам через `text.split()`.

- `chunk_size` - размер базового чанка в словах.
- `overlap` - перекрытие чанков в словах.
- Если хвост после последнего полного чанка `<= 40%` от `chunk_size`, он приклеивается к последнему чанку.
- Если хвост `> 40%` от `chunk_size`, создается отдельный последний чанк.
- Последний чанк может быть больше `chunk_size`; это нормальное поведение.

Границы чанков выводятся как 1-based inclusive: например, `1-80`.

## Answerer

`simple` answerer является extractive-компрессором:

- выбирает предложения только из найденных чанков;
- не использует весь документ;
- не генерирует факты из внутренних знаний;
- не вызывает внешние LLM;
- при отсутствии найденных источников возвращает: `В документе нет достаточной информации для ответа.`

## Правило хвоста

Если остаток после последнего полного чанка `<= 40%` от `chunk_size`, он приклеивается к последнему чанку. Иначе создается отдельный чанк.

## Ограничения MVP

В первой версии не обязательны:

- поддержка `docx` и `pdf`;
- YandexGPT, GigaChat или локальная LLM;
- neural embeddings;
- FAISS, ChromaDB, LangChain, LlamaIndex и другие крупные RAG-фреймворки;
- UI, БД, папки `src/`, `configs/` и дополнительная архитектура.

Эти возможности можно рассматривать как будущие расширения.

## Локальные файлы

`document.txt` и `test_document.txt` добавлены в `.gitignore` как локальные файлы для ручной проверки. Общий шаблон `*.txt` не используется, чтобы не скрывать нужные текстовые файлы.

## Пример запуска

```bash
python rag_query.py --document ./document.txt --question "Какая цель программы?"
```

Пример формата вывода:

```text
Вопрос:
Какая цель программы?

Ответ:
Программа предназначена для поиска ответов по одному текстовому файлу.

Источники:
1) chunk 1, score=1.000, words=1-80
Программа предназначена для поиска ответов по одному текстовому файлу...
```

## Ручная проверка

```bash
python rag_query.py --document document.txt --question "Какая цель программы?"
python rag_query.py --document document.pdf --question "Тест"
python rag_query.py --document empty.txt --question "Тест"
```

Проверка правила хвоста:

```powershell
(1..112 | ForEach-Object { "слово$_" }) -join " " | Set-Content -Encoding UTF8 document.txt
python rag_query.py --document document.txt --question "Тест"

(1..115 | ForEach-Object { "слово$_" }) -join " " | Set-Content -Encoding UTF8 document.txt
python rag_query.py --document document.txt --question "Тест"

(1..150 | ForEach-Object { "слово$_" }) -join " " | Set-Content -Encoding UTF8 document.txt
python rag_query.py --document document.txt --question "Тест"
```

Проверка retrieval:

```powershell
@"
Программа проверки документов предназначена для поиска ответов по одному текстовому файлу.
CLI принимает путь к документу и вопрос пользователя.
Retrieval разбивает документ на фрагменты и выбирает наиболее релевантные источники.
BM25 хорошо находит точные совпадения слов.
TF-IDF по символьным n-граммам помогает при разных формах русских слов.
Финальный ответ будет сформирован на следующем этапе.
"@ | Set-Content -Encoding UTF8 document.txt

python rag_query.py --document document.txt --question "Что принимает CLI?"
python rag_query.py --document document.txt --question "Зачем нужен BM25?"
python rag_query.py --document document.txt --question "Как работает retrieval?"
python rag_query.py --document document.txt --question "Какая погода завтра?"
```
